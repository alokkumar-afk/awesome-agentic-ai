# Contributing to Awesome Agentic AI

Thank you for helping improve Awesome Agentic AI.

This repository is a **curated resource, not a directory**. A project, paper, course, tutorial, tool, or guide should be added because it is genuinely useful to people learning, building, evaluating, securing, or operating Agentic AI systems.

## Before You Submit

Please check that the resource:

- Is directly relevant to Agentic AI or AI agent engineering.
- Has clear documentation or a useful technical explanation.
- Is actively maintained, historically important, or uniquely valuable.
- Adds something meaningfully different from resources already listed.
- Uses a stable canonical URL.
- Does not contain affiliate or referral parameters.
- Does not rely on misleading claims, fake benchmarks, or inflated marketing language.
- Fits an existing section or clearly justifies a new one.

Commercial projects may be included when their technical value is substantial and the entry is useful to the community without turning the list into an advertisement.

## What We Usually Accept

Examples include:

- Agent frameworks and SDKs.
- Protocols and interoperability standards.
- Open-source AI agent tools.
- MCP resources.
- Agent evaluation frameworks.
- Agent benchmarks.
- Observability and tracing tools.
- Security and guardrail resources.
- High-quality technical guides.
- Structured courses and tutorials.
- Important research papers.
- Well-maintained example repositories.
- Production engineering resources.

## What We Usually Do Not Accept

- Generic AI tools with little connection to agents.
- Thin wrappers around existing APIs with no meaningful technical value.
- Unmaintained or archived projects without historical importance.
- Affiliate links.
- Referral links.
- Link-exchange requests.
- SEO-only submissions.
- Duplicate projects with no clear differentiator.
- Promotional landing pages with little technical content.
- Lists that simply copy resources from other lists.
- Low-quality AI-generated articles.
- Projects with misleading descriptions or unverifiable claims.

## Entry Format

Use this format:

`- [Project Name](canonical-url) - One concise sentence explaining what it is and why it is useful.`

Please:

- Keep descriptions factual.
- End descriptions with a period.
- Avoid claims such as "best", "leading", "revolutionary", or "game-changing" unless they are part of an official title.
- Do not include star counts, customer counts, or other fast-changing metrics.
- Use the project's canonical documentation or repository URL.
- Keep entries alphabetically ordered within a relevant section where practical.

## Pull Request Guidelines

1. Prefer one resource per pull request.
2. Use a clear title such as `Add Project Name to Evaluation`.
3. Explain why the resource belongs in this list.
4. Disclose whether you are affiliated with the project.
5. Place the resource in the most relevant existing section.
6. Check spelling, grammar, and Markdown formatting.
7. Verify that every link you changed works.
8. Do not make unrelated formatting changes in the same pull request.
9. Do not modify `.github/`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, or repository policy files unless the pull request is specifically about repository maintenance.
10. Do not add executable scripts or GitHub Actions workflows as part of an ordinary resource submission.

## Review and Approval

All pull requests are manually reviewed by the repository maintainers.

Opening a pull request does **not** give a contributor permission to change the main repository. A proposed change only becomes part of `main` after it satisfies repository rules and receives the required maintainer approval.

Maintainers may:

- Approve a contribution.
- Request changes.
- Move an entry to a different category.
- Edit wording for consistency.
- Reject a submission that does not meet the curation standard.
- Close spam, promotional, or irrelevant pull requests.

## Self-Promotion and Conflict Disclosure

You may submit a project you maintain or work for, but you must disclose that relationship in the pull request.

Affiliation does not automatically disqualify a resource. The same inclusion criteria apply to maintainers, companies, contributors, and third parties.

## Updating Existing Entries

Pull requests that improve existing entries are encouraged, including:

- Replacing deprecated URLs.
- Removing archived or abandoned resources.
- Correcting inaccurate descriptions.
- Moving a resource to a more appropriate section.
- Updating a project after a major rename or migration.

## Removing Resources

A project may be removed when it:

- Becomes unmaintained.
- Is archived without historical importance.
- Changes into something outside the scope of this repository.
- Develops serious security or trust concerns.
- No longer provides meaningful technical value.
- Repeatedly uses the repository for promotional spam.

## New Categories

Open an issue before creating a major new category. Explain:

- Why the category belongs in an Agentic AI resource list.
- Which resources would initially populate it.
- Why those resources do not fit an existing category.

## Security

Do not disclose security vulnerabilities in a public issue or pull request. Follow [SECURITY.md](SECURITY.md).

## Code of Conduct

By participating in this repository, you agree to follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
